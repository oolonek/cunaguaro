# Wikidata chemical identifier lookup

## Fields and semantics

- [InChIKey (P235)](https://www.wikidata.org/wiki/Property:P235) is an **external identifier** for the hashed *full standard* InChI; its stated format is `[A-Z]{14}-[A-Z]{10}-[A-Z]`. Match the **entire** `annotation_hits.library_inchikey`, not its first connectivity block. [PubChem CID (P662)](https://www.wikidata.org/wiki/Property:P662) is PubChem's **Compound** ID (not Substance ID/P2153), stored as an external-identifier string; its stated format is `[1-9]\d{0,8}`. Preserve the CID as text.
- Both properties declare [single-value and distinct-values constraints](https://www.wikidata.org/wiki/Property:P235#P2302) ([P662 constraints](https://www.wikidata.org/wiki/Property:P662#P2302)), but [constraints are guidance, not enforced uniqueness](https://www.wikidata.org/wiki/Help:Property_constraints_portal). P235 even lists exceptions to distinct values; P662 lists exceptions to both. Never infer one item per key or one CID per item; preserve all distinct item/CID matches and flag ambiguous mappings rather than silently choosing one. A matching item may have no CID.
- An item label is its language-specific name, not a chemical synonym inferred from a key or CID ([Wikidata labels](https://www.wikidata.org/wiki/Help:Label)). Only `rdfs:label` with language tag `en` is an *English* label. The [WDQS label service](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#Label_service) falls back to the QID when no requested-language label exists, so its `?itemLabel` is **not** proof an English name exists. Keep missing English labels empty/null; do not substitute a QID, alias, another language, or the key as an English name. [Q844839](https://www.wikidata.org/wiki/Q844839) is the crab *Callinectes sapidus* (the crate's namesake), not a chemical mapping.

## Recommended exact-match query

[Wikidata's access guidance](https://www.wikidata.org/wiki/Wikidata:Data_access/en#Wikidata_Query_Service) recommends WDQS for narrowly scoped known characteristics and documents `GET`/`POST https://query.wikidata.org/sparql`; use direct equality on P235, **not** fuzzy/text search or `FILTER(REGEX(...))`. For each bounded chunk of distinct, complete keys (e.g. 25; heuristic, **not** a documented service limit), query:

```sparql
PREFIX wd: <http://www.wikidata.org/entity/>
PREFIX wdt: <http://www.wikidata.org/prop/direct/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>
SELECT DISTINCT ?key ?item ?cid ?englishLabel WHERE {
  VALUES ?key { "JBFOLLJCGUCDQP-UHFFFAOYSA-N" }
  ?item wdt:P235 ?key .
  OPTIONAL { ?item wdt:P662 ?cid . }
  OPTIONAL { ?item rdfs:label ?englishLabel . FILTER(LANG(?englishLabel) = "en") }
}
```

Replace the example `VALUES` literal with each key as its own quoted, properly SPARQL-escaped literal (or restrict inputs to the exact [P235 uppercase/hyphen format](https://www.wikidata.org/wiki/Property:P235#P1793)); **separately URL-form-encode the entire SPARQL query** as the `query` parameter. For large queries [POST body must contain URL-escaped `query=...`, not raw SPARQL](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#SPARQL_endpoint); small GET requests are cacheable, POST requests are not. Set `Accept: application/sparql-results+json`; parse the [standard SPARQL JSON bindings](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#SPARQL_endpoint), with `?item` as the Wikidata entity URI and optional `?cid`/`?englishLabel` absent when missing. A key with **no matching binding** has no *best-ranked* P235 statement in the current query-service snapshot, not proof that no chemical exists. Iterate input keys as well as returned rows so misses are recorded; chunk query results are **not** necessarily one row per input (multiple items/CIDs create multiple bindings). The example key was checked against the live endpoint and returned [Q104667549](https://www.wikidata.org/wiki/Q104667549), English label `3,4,5-Trihydroxy-6-[5-hydroxy-2-(4-hydroxyphenyl)-4-oxochromen-7-yl]oxyoxane-2-carboxylic acid`, CID `5387370` (single-key observation, not evidence of general uniqueness or a benchmark).

[Wikidata rank documentation](https://www.wikidata.org/wiki/Help:Ranking#How_to_query_and_filter_among_ranks) states `wdt:P235` and `wdt:P662` expose *truthy/best-ranked* statements: preferred if any, otherwise normal, **never deprecated**. This may omit a normal statement when another statement for the same property is preferred. If the product instead needs *all nondeprecated* matches, inspect statement nodes (`?item p:P235 ?statement . ?statement ps:P235 ?key ; wikibase:rank ?rank . FILTER(?rank != wikibase:DeprecatedRank)`) and likewise inspect P662 statement ranks; this is a different policy and can include non-best normal claims. Do not treat deprecated identifier claims as current matches or conflate a partial-key hit with an exact match.

## API alternative and operational limits

- [Action API `wbsearchentities`](https://www.wikidata.org/wiki/Special:ApiHelp/wbsearchentities) searches **labels/aliases**, not P235 claims (its `limit` maximum is 50 and `continue` offset maximum is 10,000). If using Action API search instead, [WikibaseCirrusSearch `haswbstatement:P235=...`](https://www.mediawiki.org/wiki/Help:Extension:WikibaseCirrusSearch/en#haswbstatement) searches statements case-insensitively; its documented string quoting syntax is `haswbstatement:"P235=VALUE"`. Follow [Action API `list=search` continuation](https://www.mediawiki.org/wiki/API:Search/en) (response's `continue` fields, notably `sroffset`; default 10, documented `srlimit` up to 500), verify returned item P235 claims/ranks and the full exact value, then retrieve needed labels/CIDs. Search hits, especially truncated pages or unverified ranks, are not authoritative matches; prefer WDQS equality for this workload.
- [WDQS manual](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#Query_limits): **60-second hard deadline**, per user-agent-plus-IP budget of **60 processing-seconds per 60 seconds**, **30 errored queries/minute**, currently **five parallel queries/IP**; exceeded quotas yield HTTP 429 and `Retry-After` specifies when to try again. These are *not* a per-key batch-size guarantee. Use a descriptive contactable `User-Agent`, `Accept-Encoding: gzip,deflate`, modest serial bounded chunks, and respect 429/`Retry-After` ([Wikidata access best practices](https://www.wikidata.org/wiki/Wikidata:Data_access/en#Access_best_practices)). An HTTP/transport/parse/timeout error is **not** an empty result: do not mark that chunk processed; checkpoint only successfully parsed complete chunks so interrupted runs resume. The WDQS [2026–2027 backend migration](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service/WDQS_backend_update) will introduce v2 endpoints; avoid assuming current endpoint details are permanent.

## Per-spectrum and feature annotations: Wikidata boundary

- **Items are not required for every observation.** Wikidata accepts an item if it has a valid Wikimedia sitelink, is a clearly identifiable entity describable with serious publicly available references, **or** fulfills a structural need; borderline cases are decided by its community. Do not create a Wikidata item merely because a run, spectrum, feature, or search hit has a local row/identifier. Keep those records in an external dataset or local graph; link only independently eligible items (for example, an identified compound, dataset, publication, or method when applicable). [Wikidata notability policy](https://www.wikidata.org/wiki/Wikidata:Notability)
- **Keep evidence distinct from identification.** Model a feature's measured mass, retention time, intensity, sample/run, peak or scan, candidate matches, scores, method/software/version, and original data/source as scoped observations outside Wikidata; a scored library match or InChIKey lookup is a *candidate*, not proof the compound occurs in that sample. Wikidata [statements](https://www.wikidata.org/wiki/Help:Statements) assert property–value pairs about an item; [qualifiers](https://www.wikidata.org/wiki/Help:Qualifiers) delimit a statement (e.g. method or time) but should not carry an entire observation whose main claim is meaningless without them; [references](https://www.wikidata.org/wiki/Help:Sources) identify its evidential source (e.g. `stated in` P248 for a publication/database item, `reference URL` P854 for an online record). Only publish an appropriately scoped, verifiable claim there when its property and subject actually express the intended fact; do not turn a tentative hit into an unconditional “found in” claim.
- **Identify the right level.** The [ratified PSI USI 1.0 specification](https://github.com/HUPO-PSI/usi/blob/master/Specification/USI_FullSpecification_1.0.0_final.pdf) identifies a *spectrum* with `mzspec:<collection>:<msRun>:<indexType>:<indexNumber>`, optionally followed by an interpretation; its run-only form is `mzspec:<collection>:<msRun>`. `scan`, `index`, and `nativeId` have different meanings; the optional interpretation *may be incorrect*. USI is not a generic chromatographic feature ID and neither a scan number nor a feature row number is globally unique alone: retain collection, run/file, indexing scheme, and the feature table or analysis that issued a feature ID. Use a USI only where those required spectrum coordinates and a suitable collection identifier exist; otherwise use a stable, resolvable identifier in the owning repository/local graph rather than inventing a USI.
- **Bridge instead of copying the graph.** Link local observation/feature/hit IRIs to established Wikidata item IRIs and existing appropriate identifiers where the entity matches; keep scores and per-run provenance locally. [Wikibase's RDF mapping](https://www.mediawiki.org/wiki/Wikibase/Indexing/RDF_Dump_Format) exposes `wdt:` direct *best-ranked* values but requires `p:` → statement, `ps:` main value, `pq:` qualifiers, and `prov:wasDerivedFrom` → `pr:` references for provenance-preserving joins. An external identifier property links **items** to records about those items, not every unqualified local event ([external identifiers](https://www.wikidata.org/wiki/Wikidata:External_identifiers)). If a genuinely useful missing identifier/property is needed, [check existing properties and proposals first](https://www.wikidata.org/wiki/Wikidata:Property_proposal/Header); [creation requires a formal proposal, community consensus, and at least one week](https://www.wikidata.org/wiki/Wikidata:Property_creation), not just a new column or identifier namespace.
